NixOS Recovery

Your main system didn't start, or something on it broke. Find what you see below and follow the steps.

Start here

Try an older generation

Reboot into the main disk and pick a previous NixOS generation in its boot menu. Most broken updates are fixed by this alone.

Read what failed

Click Main System Logs in the dock. It shows the warnings and errors from the main system's last boot, without changing anything.

Fix it from inside

Click Enter Main System for a root shell inside the main installation, then roll back or rebuild as described below.

Problems

It broke after an update or a config change

Black screen, no login, a service fails, the desktop doesn't start.
  1. Easiest: reboot and choose an older generation in the main boot menu. If it works, make that the default from inside the main system later.
  2. Otherwise click Enter Main System and roll back to the previous generation: 
    nixos-rebuild boot --rollback
  3. To fix the configuration instead, set your uncommitted changes aside (they are kept and can be brought back with git stash pop), then rebuild: 
    cd /home/abdulrahman/system-conf
git status
git stash push --include-untracked --message "set aside from recovery"
nixos-rebuild boot --flake /home/abdulrahman/system-conf#default
  4. See what changed between two generations (if nvd is installed on the main system): 
    ls -l /nix/var/nix/profiles/ | grep system-
nvd diff /nix/var/nix/profiles/system-41-link /nix/var/nix/profiles/system-42-link

nixos-rebuild boot only changes what starts on the next boot. Nothing runs until you reboot into the main disk.

The computer doesn't find the main system

No boot menu, "no bootable device", or it always lands here.
  1. Click Repair Main Bootloader and type REPAIR. It reinstalls Limine and the boot menu on the main disk for the current generation, the same way the installer does.
  2. If that reports a damaged EFI partition, check it first, then repair again: 
    sudo fsck.vfat -a /dev/disk/by-uuid/FE76-C46F
  3. Still nothing? Open the firmware's one-time boot menu and choose the Samsung 990 Pro, or check the firmware's boot order (Reboot to Firmware Setup in the session menu).

Boot hangs or drops to emergency mode

Stuck on a start job, "emergency mode", or a filesystem won't mount.
  1. Click Main System Logs and look for the first red lines near the end; failed mounts and units are named there.
  2. Click Enter Main System. If the main system's start-up rollback was interrupted, it says the root or home subvolume is missing and offers to restore it; type RESTORE. That creates exactly what the next normal boot would.
  3. A full disk also stops boots. Check it from inside the main system: 
    btrfs filesystem usage /
ncdu -x /persist

The disk is full

"No space left on device", builds or boots fail.
  1. Click Enter Main System, then find what grew: 
    btrfs filesystem usage /
ncdu -x /persist
ncdu -x /nix
  2. Remove store paths no generation uses. This keeps every generation you can boot: 
    nix-collect-garbage

Only delete old generations (nix-collect-garbage -d) when you're sure you won't need to boot them again.

Random crashes, freezes or corrupted files

The machine reboots or freezes, and it isn't one specific update.
  1. Test the RAM: reboot, and in the recovery disk's boot menu choose Memtest86+ (RAM test). Let it run at least one full pass.
  2. Watch temperatures and load with System Monitor in the dock, or: 
    sensors
  3. Check the drives with Disk Health.

A disk might be failing

SMART warnings, I/O errors in the logs, files that won't read.
  1. Click Disk Health for every drive's SMART status.
  2. Copy what matters to the recovery disk's data partition (/mnt/SN350) first. Mount the main system read-only: 
    sudo mkdir -p /mnt/main
sudo mount -o ro,subvol=persist /dev/disk/by-uuid/ddb4bdb8-c522-4420-ba2d-ace00fc2054b /mnt/main
rsync -aHAX --info=progress2 /mnt/main/home/abdulrahman/Documents/ /mnt/SN350/rescue/Documents/
  3. For a disk that throws read errors, image it with ddrescue instead. Replace /dev/DISK with the failing disk; the same command resumes where it stopped: 
    sudo ddrescue -d /dev/DISK /mnt/SN350/disk.img /mnt/SN350/disk.map

Check device names with lsblk -f first; nvme0n1 and friends can change between boots. The image needs as much free space as the whole disk.

No internet here

The browser can't load pages, downloads fail.
  1. Wired Ethernet connects by itself. For Wi-Fi, use the network button in the bar, or: 
    nmtui
  2. Find out where it stops: 
    ip -br address
ping -c3 1.1.1.1
ping -c3 nixos.org
    If the first ping works and the second doesn't, it's DNS.

This recovery desktop shows a black screen

The recovery disk itself boots, but the screen stays dark.
  1. Reboot and choose the safe-graphics entry under NixOS Recovery in the recovery disk's boot menu. It runs without the NVIDIA driver.
  2. A text console always works: press Ctrl+Alt+F2 and log in.

Which password?

Login, sudo and GParted ask for a password.

Everywhere on the recovery it is the main system's root password, as it was the last time the recovery was updated.

Good to know

Entering is not read-only

Enter Main System runs the main system's start-up steps against its real saved state, like a boot does. To only look, use Main System Logs or mount it read-only.

Separate from the main system

The recovery has its own browser profile and home folder on the recovery disk. Nothing here changes the main system unless you enter or mount it.

Keep it current

From the main system: nix run .#recovery-update in the repository. Try changes first with nix run .#recovery-vm.

Ask for help

Claude Code and Codex are installed and signed in: Assistants in the desktop menu or launcher, or claude, codex, claudex, codexx in a terminal. If one asks you to sign in, use /login or codex login.

Share an error

Take a screenshot from the bar, or copy logs with journalctl -b -1 -p err | wl-copy, and paste them where you ask.
